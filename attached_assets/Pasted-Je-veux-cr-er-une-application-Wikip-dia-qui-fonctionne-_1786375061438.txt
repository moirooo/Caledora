Je veux créer une application Wikipédia qui fonctionne à partir de fichiers texte structurés.

IMPORTANT :
Je ne veux PAS que l’IA génère, reformule, enrichisse ou invente du contenu.

L’application doit uniquement lire les données présentes dans le fichier importé et les placer automatiquement au bon endroit dans la page Wikipédia.

Le fichier source est la seule source de vérité.

Si une information n’est pas présente dans le fichier :
ne rien inventer,
ne rien compléter,
ne rien supposer.

==================================================
1. PRINCIPE GÉNÉRAL
==================================================

Je veux pouvoir créer une page Wikipédia simplement en important un fichier texte structuré.

Exemple :

je clique sur :

Créer une page

je choisis :

Catégorie : Éducation
Type : Université

puis j’importe :

Universa_Lacora.txt

L’application lit le fichier et construit automatiquement la page Wikipédia.

Elle doit uniquement répartir les informations selon les balises du fichier.

==================================================

3. INTERPRÉTATION DES BALISES
==================================================

L’application doit comprendre automatiquement :

[TITRE]
→ titre principal de la page

[SOUS-TITRE]
→ sous-titre éventuel

[ALIASES]
→ noms alternatifs de la page

[INTRODUCTION]
→ texte situé avant le sommaire

[INFOBOX]
→ données de l’infobox

Format :
clé = valeur

Exemple :
Fondation = 1684

La partie avant "=" devient le label.
La partie après "=" devient la valeur.

[IMAGE_INFOBOX]
→ image principale de l’infobox

[SECTION]
→ titre H2

[SOUS-SECTION]
→ titre H3

[SOUS-SOUS-SECTION]
→ titre H4

[TEXTE]
→ paragraphe

[LISTE]
→ liste à puces

[LISTE_NUMEROTEE]
→ liste numérotée

[IMAGE]
→ image dans l’article

[TABLEAU]
→ tableau Wikipédia

[LIENS]
→ liens internes

[REFERENCES]
→ notes et références

[BIBLIOGRAPHIE]
→ bibliographie

[CATEGORIES]
→ catégories en bas de page

==================================================
4. AUCUNE GÉNÉRATION DE CONTENU
==================================================

RÈGLE ABSOLUE :

L’application ne doit jamais créer un texte qui n’existe pas dans le document.

Exemple :

si le fichier contient :

Fondation = 1684

l’application peut afficher :

Fondation : 1684

mais elle ne doit jamais écrire :

« L’université fut fondée en 1684 dans le contexte du développement intellectuel de Caledora. »

car cette phrase n’existe pas dans le fichier.

Même chose pour les sections.

Si le fichier ne contient aucune section :

Sport

alors ne pas créer de section Sport.

==================================================
5. INFOBOX
==================================================

L’infobox doit être construite automatiquement uniquement depuis le bloc :

[INFOBOX]

Chaque ligne :

clé = valeur

devient une ligne de l’infobox.

Exemple :

[INFOBOX]

Fondation = 1684
Type = Université publique
Étudiants = 52 000

doit produire :

Fondation      1684
Type            Université publique
Étudiants       52 000

L’ordre du fichier doit être conservé.

Ne pas ajouter automatiquement de champs.

==================================================
6. SOMMAIRE
==================================================

Le sommaire doit être généré automatiquement à partir des balises :

[SECTION]
[SOUS-SECTION]
[SOUS-SOUS-SECTION]

Exemple :

[SECTION]
Histoire

[SOUS-SECTION]
Fondation

[SECTION]
Campus

donne :

Sommaire

1 Histoire
  1.1 Fondation

2 Campus

==================================================
7. IMAGES
==================================================

Les images peuvent être ajoutées séparément dans l’application.

Dans le fichier texte :

[IMAGE]

fichier = campus.jpg
légende = Vue du campus
alignement = droite
taille = 300
alt = Vue aérienne du campus

L’application cherche l’image importée portant le même nom.

Si l’image n’existe pas :
afficher un emplacement manquant ou demander de l’importer.

Je dois ensuite pouvoir :

ajouter une image
supprimer une image
remplacer une image
modifier sa légende
modifier son alt
modifier son alignement
modifier sa taille

==================================================
8. LIENS INTERNES
==================================================

Deux systèmes doivent fonctionner.

SYSTÈME 1 :

Dans le fichier texte, je peux écrire :

[[Caledora]]

Cela signifie que Caledora est un lien interne.

Si la page Caledora existe :
lien bleu.

Si elle n’existe pas :
lien rouge.

SYSTÈME 2 :

Je peux également utiliser le bloc :

[LIENS]

Caledora
Campus Aurea
Sciencia Park

L’application affiche ces pages dans « Voir aussi ».

==================================================
9. FORMAT DES LIENS DANS LE TEXTE
==================================================

Exemple :

[TEXTE]
Universa Lacora est située dans [[Caledora]], à proximité de [[Sciencia Park]].

L’application affiche :

Universa Lacora est située dans Caledora, à proximité de Sciencia Park.

Caledora et Sciencia Park sont cliquables.

14. METTRE À JOUR AVEC UN NOUVEAU FICHIER TXT
==================================================

Ajouter :

« Mettre à jour depuis un fichier »

Je peux réimporter un nouveau TXT.

L’application relit le fichier.

Elle compare les champs structurés avec la version existante.

Afficher les différences avant validation.

Exemple :

Fondation
ancien : 1684
nouveau : 1686

Population étudiante
ancien : 52 000
nouveau : 54 300

Je choisis ensuite :

Appliquer

ou

Ignorer.

18. POINT IMPORTANT
==================================================

Ne pas utiliser un LLM pour parser le document.

Le format est suffisamment structuré pour être traité de manière déterministe.

Créer un parser qui lit les balises.

Ainsi :

même fichier
=
toujours exactement la même page.

Aucune hallucination.
Aucune reformulation.
Aucune donnée inventée.
